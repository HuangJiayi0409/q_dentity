# 本轮 CAS 方法能力与边界

这里报告当前 `agent_v2` 的注册和本轮执行结果。历史 Train 成绩、旧完整流水线曾经成功的记录，以及生成但尚未检查的 Lean 脚本，都不提升本表等级。

统一注册表有 12 个方法族。差分／望远镜和递推由主任务提供真实 Train/Lean 证据；本目录负责其余 10 项，严格按下表顺序逐项适配。最终独立请求验收保存在 `final_v2/validation.json`：7 项 L2、3 项 L0、40 个场景、0 个形式化证书、0 个新增形式化义务。此处不是 Train 成功率实验。

|---|---|---|---|---|---|

所有 L2 的正式前端都先核验 Source 完整性，再明确返回 `not_applicable`，原因是缺少当前 Source 到该核心请求的已验证导出。本轮不把任意 Train 公式猜成核心输入，不创建没有可执行契约的 Outlet。外部显式提供并绑定的 `core_request` 可以通过统一适配器或 `method-demo` 运行。

## 公共请求格式与隔离

```json
{"schema_version": 1, "method": "coefficient", "input": {"lhs": {"op": "integer", "value": 1}, "rhs": {"op": "integer", "value": 1}}}
```

必须恰含这三个字段，版本必须是整数 1。输入不允许指定导入路径、函数、脚本、Lean 命令、题号或证书。独立子进程只调用固定登记的现有核心；未使用 `eval`/`sympify` 解析用户表达式文本。公共结构限制为 4096 个 JSON 节点、深度 32、字符串 1024 字符、整数绝对值通常不超过一百万。每个相同 atom key 在请求内只允许一个 display 含义。

每次运行保存请求、契约、命令、退出码、stdout/stderr、成本、原始输出、Python/SymPy 版本，以及本方法实际核心与依赖的执行前后哈希。返回结果还会校验版本、请求绑定、核心哈希、成功载荷的必要字段和矩阵维数。符号成果只有 `symbolic_constructed/translation_pending`；`C_partial=[]`、`O_res=[]`、`original_identity_proved=false`。

`workflow/matrix_symbolic.py` 是本轮显式复用的唯一旧 workflow 数学辅助文件：它只负责精确标量／矩阵序列化和残差核对，不含选路或会话控制。相邻 `workflow/__init__.py` 只有文档字符串，二者都被逐方法登记、冻结和核对。没有恢复 `workflow.contracts`、`workflow.preprocessed` 或旧 Agent。L0 的依赖缺口静态证据见 `dependency_boundaries.json`。

预算耗尽于启动前时不启动进程；已启动的超时会保存真实进程报告。进程清理失败优先归为 `environment_blocked/cleanup_failed`；非零退出无输出、零退出无输出、损坏 JSON、绑定错误、成功输出与非零退出不一致分别分类。数学上未找到构造不归成环境错误，也不推断恒等式不可证明。

## 各请求的有限输入范围

可直接运行的完整 JSON 例子位于 `final_v2/<method>/example_request.json`。

- 系数：`{lhs,rhs}` 或 `{goals:[...]}`，每层 1–16 分支。表达式支持 integer、独立 atom、负号、0–8 次幂、二元加减乘。拒绝 `closed_by_preparation` 等未经 Lean 证实的关闭标记。
- 乘积：有类型 Eq/Finset.prod/Finset.range 语法树，显式 lambda 和自然数运算。仅验证契约，不启动核心。
- 插值：`{goal:{lhs,rhs,type:"K",char_zero:<bool>},max_degree:0..8}`。必须明确域；非 CharZero 的次数大于 1 且缺节点分离证明时，原核心诚实拒绝。
- 非交换：有限有类型词的 Eq，显式幂最多 12。仅验证契约。
- 组合：有限范围加权求和 Eq。仅验证契约。
- 差分环：`{goal:{lhs,rhs,hypotheses:[{name:"h0",lhs,rhs},...]},max_degree:0..16,max_unknowns:1..10000}`，至多 16 个显式关系。输出保留原关系乘子，不能将关系自行解释为已证明前提。
- 核变换：`operation=inverse|composition`，`matrix`、`proposed_inverse`，复合时还需 `target_kernel`，显式 `size=1..4,type="K",vector="v"`。矩阵对象含 `display` 与方阵 `entries`；标量用受限精确树表示。
- 谱：`weight,left,right` 各含 `display/entries`，同一 `size=1..4,type="K"`。
- 行列式：`matrix,size=1..4,type="K",reverse:<bool>`。
- MacMahon：`numerator,denominator_monomials,grading,eliminate`。整数、已声明符号及受限算术树；最多 8 因子、8 外部变量、4 辅助变量，指数绝对值最多 8。每个几何因子须有严格正外部权重，`ge/ct` 明确指定。核心资源为次数 32、状态 16、项数 256，进程墙钟另行限制。结果为泛型形式参数表达式，特化仍需额外验证。

## 其它现有核心入口没有被忽略或冒充已接通

`p1/core.py` 还有下表所列模式。这些是现有方法族内的求解器／表示变体，不通过改名增加方法数量。本轮注册 `difference_ring` 的多项式关系核心，**不代表**所有差分域／PLDE 模式都可通过 agent_v2 调用。

| 原核心模式／入口 | 归属与当前接入情况 |
|---|---|
| q_gosper、q_zeilberger、parameterized_q_gosper | 望远镜／递推族；现有 `core-demo` 支持明确的独立请求，前两者另由特定原题结构的 L3 适配器使用 |
| rational_omega | MacMahon 族；本轮真实 L2 已接 |
| difference_ring、difference_field、finite_difference_ring | 差分环／差分域族的另一组核心模式；原入口存在，本轮未接这些模式的完整输入契约和重放，不能由本表 L2 推出它们已支持 |
| difference_equation、difference_system | 高阶 PLDE／耦合系统扩展；原 `qplde.py` / `qpisigma_system.py` 存在，本轮未接 |
| q_ore、q_zeilberger_joint、q_holonomic、parameterized_q_system | 递推／算子／矩阵移位模块扩展；原入口存在，本轮未接，不把条件模块方程当成原题事实 |
| p1/bibasic.py 及 bibasic_pipeline.py | 望远镜族的双基分支；原核心保留，尚无本轮 typed v2 适配与原域 Lean 出口 |
| p1/multisum.py 及 multisum_pipeline.py | 望远镜／递推族的多重和有界有理证书分支；原核心保留，尚无本轮 v2 适配，不能宣称一般多重和已支持 |

这些未接的扩展没有进入正式 Graph 的可执行候选。现有算法源码未被删除、替换或复制成另一个方法。已退休完整流水线依赖断裂的现状是明确边界，历史证明不冒充本次验收。

## 证据、顺序与复现

`final_v2/execution_order.json` 保存严格串行的开始／结束时间：每个方法完成正例、结构不匹配、规范化与不入 C 检查，再处理数学失败／预算耗尽，之后才开始下一方法。7 个 L2 使用本次新进程执行现有数学核心；L0 正例是输入契约接受且明确能力不可用，不是数学构造成功。

```bash
python3 agent_v2/generated/closure_and_methods_20261111/method_adaptation/validate_adaptations.py --output /tmp/agent_v2_methods_fresh
python3 -m agent_v2.cli method-demo --method macmahon --input agent_v2/generated/closure_and_methods_20261111/method_adaptation/final_v2/macmahon/example_request.json --seconds 30
```

复现目录必须不存在。独立请求验收不读取 benchmark、不调用模型、也不编译 Lean。它不能代替主任务的真实原题验收。

开发阶段曾将 product 的规则选择输出误标为符号构造；审阅后已撤销，保留 `product/review_correction.json` 与原始记录，最终等级为 L0，不能把旧 positive 目录计为成功。最初 `final/` 证据脚本把不可变规范化 tuple 与 JSON list 直接比较，停在插值断言；实际核心结果正确。该次保留，修的是 generated 脚本，最终只计 `final_v2/`，不择优合并。单元测试还发现过构造示例共享 Python 对象导致负例同时修改两侧的问题；修正负例副本后重验通过，未改变旧数学算法。

独立审阅补了成功载荷缺失、请求哈希错误、L0 禁止启动、atom 含义一致和超时伴随清理失败检查。所有故障注入只验证接口分类，明确不算数学成功或 Lean 成功。
