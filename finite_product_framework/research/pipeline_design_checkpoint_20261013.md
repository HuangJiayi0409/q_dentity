### 审核标准与结论

符号证明模块应明确：输入如何表示、程序执行什么精确符号操作、构造或使用什么证书、如何闭合原域/边界，以及如何验证原始声明。外部 CAS 不是必要条件；Lean 内的精确正规化和可执行重写也属于符号计算。数值试验和仅有数学定理而无可执行处理过程，不能当作自动构造能力。

按**运行时主要行为**，目前分为：

- **4 条符号证书构造流程**：望远镜、递推、插值/主部、差分环。程序从表达式计算未知的见证、系数或关系乘子，但都受输入语法和重建能力限制。
- **5 条正规化或模板流程**：系数、乘积、非交换、组合双射/对合、MacMahon。具有可执行的精确变换，适合放进模块；须注明模板范围，不宣传成一般证书发现算法。
- **3 条混合流程**：核变换、谱正交、行列式。有些分支能直接做有限符号计算，一般结构分支主要依赖输入已提供证书。可保留为验证/组装组件，不宜统一标成能从原式自动产生一般结构的求解器。

这不是可靠性排名，也不是新的数学分类；是否通过原题验证与证书如何获得是两个不同维度。

### 三个容易高估的构造环节

**核反演。** [kernel_inverse](../kernel_transform/lean/Rules.lean) 应用通用逆核/复合定理后，先尝试 `assumption`，再尝试 `fin_cases`、有限求和展开与 `ring`。它验证已经出现在目标/上下文中的核，没有从一个核计算出一般闭式逆核。三角域转置分支则有独立的符号变换能力，应分开统计。

**谱正交。** [spectral_certificate](../spectral/lean/Rules.lean) 在局部上下文按类型枚举算子、本征值和函数，不综合新的算子表达式。全族正交分支依靠现成平衡、本征、单射和范数条件；简单实例的条件可以精确展开验证。因此当前主要缺的是证书的构造，而不是正交推理定理。

**行列式。** [determinant_structure](../determinant/lean/Rules.lean) 的 LU 分支使用 `apply ... <;> assumption`。符号阶数的通用定理是有效验证基础，但不是自动 LU 分解算法。显式 Vandermonde 等求值分支应保留其实际计算贡献。

### MacMahon 与组合分支的模板性质

这两类不能仅因“没有外部 CAS”就被排除；它们实际执行了精确符号重写和模板匹配。但也需要纠正“运行时自动发现证明”的印象：

- [macmahon_chain](../macmahon/lean/Rules.lean) 主要实例化已经证明的链因子化和 `omega_rectangle_evaluation`。矩形链证明的核心数学内容已在 `Rules.lean` 中；运行时不从任意约束推导新的几何乘积，也不重新发现 Gaussian 系数识别。
- [geometric_subsets 分支](../combinatorial/pipeline.py) 使用预证的 Gaussian 子集表示；反射/切换分支枚举有限映射模板，不搜索未知双射。

这些规则支持任意符号参数，区别于固定尺寸枚举；使用它们所得原题证明可以有效。未来评估应另标 `template_instantiation`，不能据此宣称一般分拆消元或双射发现能力已实现。若模块目标要求广泛的自动证书构造，这两类仍需增强。

4. **构造成功与原题成功分开。** 如 q-Zeilberger 找到高阶关系，而 Lean 只支持其一/二阶特定出口；这属于已有联系但重建不支持，不是方法范围外。
5. **按分支统计证书来源。** 使用原始假设中的条件是合法的，但“从原式计算新证书”和“验证原式已给证书”的覆盖含义不同。模板实例化也单独标注。来源应至少分为 `computed_witness`、`normalization`、`template_instantiation`、`context_certificate`，允许混合。
6. **固定实际依赖与引理。** P1 会编译完整 `Auxiliary`/`Gaussian` 基础文件，包括多项式与商的关系，不能一概称为纯定义环境。后续基线需记录算法源、规则库、依赖版本、入口范围、预算和失败分类方案。

目前已有[原题接收契约](../workflow/contracts.py)：检查原源及证明哈希、Lean 编译结果、原定理公理列表和声明上下文；结构方法还检查证书绑定。正式 worker 固定方法归属，没有从一个独立方法失败后偷偷切换其他方法。此次静态检查不等于重新执行这些检查。

## 上一轮回答正文

我读了这篇文章的第 3 节，重点核对了 **3.2 的三个符号证明后端及其 Lean 生成流程**。现在更清楚你的要求了：**你要找的是能够接收一类证明目标、自动构造完整证书、最终返回 Lean 证明的“大方法”，而不是一串可用于中间计算的算法名称。**

我之前的回答确实没有一直保持这个层级。

**文章的三个方法，完整性体现在“证书如何闭合目标”。**

| 后端 | 构造什么证书 | 怎样完成证明 |
|---|---|---|
| **SOS** | 平方和及约束乘子的多项式分解 | 搜索数值候选 → 恢复精确有理证书 → 验证恒等式及各项非负 → Lean 证明 |
| **BoxPoly** | 区间非负基函数的非负线性组合 | 区间归一化 → 线性规划 → 精确恢复 → 验证展开及区间条件 → Lean 证明 |
| **DiffSub** | 覆盖所有分支的递归代换树 | 变量排序分支 → 非负差变量代换 → 递归搜索 → 叶节点系数非负 → Lean 重建整棵证明树 |

它们并不是“半定规划、线性规划、代换”三个孤立工具，而是三个**围绕特定证书结构组织的证明器**。依据：上述论文第 3.2 节。

还有一个重要区别：文章允许后端证明原定理，也允许证明中间引理。**关键不是它必须一次解决整篇证明，而是它必须完整解决交给自己的目标。** 展开、因式分解、清分母这些操作本身不满足这一标准。

**按这个标准，q 组合恒等式应围绕以下“完整证明证书”组织。** 下面是我据此提出的架构，不是说它们已全部实现。

| 大方法 | 输入目标与核心证书 | 连贯的完整流程 |
|---|---|---|
| **有限差分证书求和** | 有限求和等式；证书是原差分或多方向通量 | 提取实际求和项与支撑 → 搜索差分证书 → 验证原域局部关系 → 求和并计算真实边界 → 与目标比较 → Lean |
| **递推证书与唯一性证明** | 两个随参数变化的表达式相等；证书是共同递推、边界修正和初值 | 从实际定义构造递推 → 验证两侧满足同一关系 → 处理推进系数及奇点 → 验证足够初值 → 唯一性闭合 → Lean |
| **嵌套和积的差分代数化简** | 可嵌入指定差分扩张的和积等式；证书是扩张中的求和、化简关系及求值对应 | 构建和积表示 → 参数化望远镜／递推求解 → 构造可验证的等式推导 → 回译并验证起点、定义域 → Lean |
| **有限基底展开与系数证明** | 可作有限多项式、Laurent 或其他基底展开的等式；证书是展开与系数关系 | 选择基底并证明支撑 → 自动展开及换序 → 完整证明系数关系 → 由基底性质恢复原式 → Lean |

这里有两点需要保持清楚。

**第一，前两条才是我们现有 P1 工作最自然的“大方法”划分。**

- q-Gosper、双基 Gosper等，主要服务于“有限差分证书求和”。
- q-WZ、q-Zeilberger、多重创造性望远镜，以及部分 Ore 构造，主要服务于“递推证书与唯一性证明”。
- 同一个多重望远镜构造也可能同时涉及差分求和与外参数递推，所以不能把这些后端强行划成互不重叠的集合。

这意味着已有算法实现仍然有用，但在对外呈现时，应当归入少数完整证明器，而不是把每个求解器都作为一条同等级 pipeline。

**第二，后两条不能仅凭名称就宣称完成。**

差分环若只输出一个形式等式，没有求值回译和起始条件证明，就仍只是计算后端；系数法若把关键系数恒等式留作未证明义务，也没有形成完整流程。第四条属于你已有的 P2 方向；当前若仍限定在 P1 的 120 条，就不应为了凑成类似论文的“三种方法”而提前扩大范围。

因此，你这篇文章给出的正确参照是：

> **按“可验证的完整证明证书”划分大方法；每个大方法内部再选择符号计算算法。**

今后评估候选方法时，我会先给出它的**输入类、证书结构、自动构造过程、Lean 闭合路径**。只有这四项能够连起来，才把它作为完整 pipeline 候选；qHyper、去奇点、解耦、线性消元等则放在相应流程内部。
