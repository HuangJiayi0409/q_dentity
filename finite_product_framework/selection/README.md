# 十二方法选择器 v1：未知并列单独标记

实现：2026-10-20。输入是公共预处理产生并核验的表达式；输出是十二方法中的一个，或“全部未知并列、未分类”，以及各分支四项评分及理由。只做结构选择，不训练模型、不读取历史结果作为特征、不预测成功概率或实际秒数。

本次按用户最新要求保留 v1 全部结构特征、21 条规则、AHP 权重和 TOPSIS 排名。十二方法全部为 `unknown` 且评分区间相同时，返回 `unclassified` / `all_methods_unknown_tied`，`selected_method` 和 `selected_route` 均为 null；名称顺序仅用于展示。未知不等于不适用，也不把十二方法探索所得的成功方法反写成分类结果。

默认只标记未分类。显式 `--unknown-policy all` 才对这类输入运行全部十二方法，默认最多4个方法并行，共用一次核验预处理，每个方法有独立的 `--seconds` 总预算及原题证据接收。即使已有方法成功，仍完成十二方法记录。**此选项的总预算不同于单首选：每方法预算从其启动时计算，另计共用预处理和分类；默认最多分配 12×900 秒方法时间，并非整题总共900秒。** 有明确选择的题仍只运行一个方法，不会在该方法失败后扩展候选。`select_method.py` 始终只分类，即使传入此选项也不运行方法。

## 使用

在项目根目录执行。当前输入接口沿用当前 Train 身份校验，不接受任意外部 Lean 文件。

```bash
# 只预处理和选择，不运行证明方法
python3 finite_product_framework/select_method.py \
  --identity FQI-POCHHAMMER-ROOTS \
  --output-root finite_product_framework/generated/my_selection

# 预处理一次，选择一个方法，再执行该方法
python3 finite_product_framework/prove_auto.py \
  --identity FQI-POCHHAMMER-ROOTS \
  --seconds 900 \
  --output-root finite_product_framework/generated/my_auto_proof

# 等价的显式自动模式
python3 finite_product_framework/prove.py --method auto --identity FQI-POCHHAMMER-ROOTS

# 全部未知并列时探索十二方法；其余输入仍只执行首选
python3 finite_product_framework/prove_auto.py \
  --identity FQI-BAILEY-INVERSION --unknown-policy all --unknown-workers 4 \
  --seconds 900 --output-root finite_product_framework/generated/my_unknown_exploration
```

自动模式总是启用核验过的公共预处理，默认 `structured` 视图；可显式指定 `--preprocessing-view expanded`。显式指定某个方法的原入口继续保持原有行为。没有恢复五核心入口，也没有修改十二方法的数学算法。

单首选预算从源快照开始计时。预处理、选择、方法分析、构造、原题验证共同消耗 `--seconds`；选择子进程另外受 `--selection-seconds` 限制，默认 10 秒。分类内部默认最多检查 100000 个 DAG 节点，输入文件不超过 64 MiB。超时或结构分析资源不足是 `selection_failed` / `resource_exhausted`，不是数学不可证明。启用未知并列的十二方法探索时，预算规则见上文，逐方法报告保存各自的完整期限。

每次运行新建 UUID 目录。`report.json` 记录总结果、各阶段事件、选中方法和实际时间；`selection/result.json` 记录全部评分。`selected` 只表示完成选择，`automatic_train_proofs` 仍为 0。只有原题 Lean 验证和原有证据审计通过后才是 `proved`。

## 流程和不变量

1. 一次核验过的预处理，得到同一份 `standard.json` 和等价证据描述符。
2. 从目标及其有界可达定义提取特征。上下文只用于条件检查，不把假设中的求和/行列式混进目标结构。
3. 21 条结构规则覆盖所有 18 个现有后端及十二方法。规则按真实分支分别打分，单个矩阵构造分支超出尺寸上限不排除其结构求值分支。
4. 对各分支执行 AHP + 固定理想点 TOPSIS；每个方法保留其最佳完整分支的得分，不能跨分支拼接优点。
5. 有选择依据时选择一个方法。原方法仍可执行自己的多个合法内部后端；评分中的 `selected_route` 是选择依据，不替换方法自身的证明计划。全部未知并列则标记未分类；只有显式启用探索才运行十二方法，成功与分类状态分别保留。
6. 方法消费同一份预处理证据，不重新预处理、不重置时间预算；原题验收契约不变。

选择子进程不调用 Lean、SymPy 或任何方法求解器。预处理和后续证明仍会使用 Lean。题号仅用于加载原题及来源校验，不用于评分；不读取 Test、旧证明、成功率表或题目家族标签。

## 特征与评分

特征来自公共 DAG 的实际常量、绑定变量、区间、已知对象及类型。只检查规范化目标及其相关定义，定义至多有界检查两层，不把定义体当成已完成的原题桥接。使用签名或已知内核接口读取运算参数；部分应用、未知常量、未支持绑定结构保留未知。一般定义并不因此变成可支持的输入。

| 指标 | 固定尺度和证据 |
|---|---|
| `structure` | 强结构模式 1，部分模式 0.5，未知 [0,1]。1 也不是求解器前端完整接受或证明成功的保证 |
| `conditions` | 已明确确认的前提数 / 该规则列出的前提数为下界；未知前提计入上界。条件与目标的参数/类型做精确绑定匹配 |
| `reconstruction` | 精确命中已接通形式 1；只有部分源表示支持 0.5；无法静态判断 [0,1]。不预先认定未来证书的边界和奇异项能闭合 |
| `conversion` | 已知入口转换数 r 时为 1/(1+r)，否则 [0,1]。转换计数不是实际运行时间 |

首版精细条件识别包括：`prod (1-x*w^j)=1-x^m` 的正阶和匹配的 `IsPrimitiveRoot w m`，以及插值入口对应目标系数域的 `Field` / `CharZero`。`Rat`、`Real`、`Complex` 的域属性按已知类型识别。合取可以拆分；`w^m=1` 不替代本原单位根，其他参数上的同名条件不算匹配。一般源分母、量化支撑、求解后出现的分母/首项条件仍标未知，不假装全部自动核查完毕。

**多数分支目前是粗结构规则，尚不能静态判断其全部适用条件和原题出口范围。** 只有明确知道当前分支不接受时才排除；未知区间原样保留。一般排名并列仍使用固定标识符顺序；若十二方法全部未知且评分区间相同，该顺序不再产生首选，而是显式报告未分类。未分类是覆盖/信息不足，不是选错了一个已有明确依据的方法。

## AHP 与固定理想点 TOPSIS

四指标顺序为结构、条件、重建、转换。初始两两比较矩阵：

```text
1    2    1    4
1/2  1    1/2  2
1    2    1    4
1/4  1/2  1/4  1
```

权重为 `(4,2,4,1)/11`，即约 `(0.3636,0.1818,0.3636,0.0909)`。这是明确声明的工程偏好，未经成功率数据训练或优化；矩阵由这些比值生成，CR=0 只说明内部一致，不能验证优先级正确。实现检验正数、互反性并拒绝 CR>0.10 的矩阵。

固定评分范围 [0,1]，令 `v_j=w_j*s_j`，加权理想点为 `w`，负理想点为 `0`：

```text
d_plus  = sqrt(sum((w_j*(1-s_j))^2))
d_minus = sqrt(sum((w_j*s_j)^2))
C       = d_minus/(d_plus+d_minus)
```

不按当前候选的最小/最大值重新归一化，增加无关候选不会改变已有分支分数。因为该得分对各指标单调，未知区间的上下端点给出优先度区间。先按下界降序，再按区间宽度升序，最后按固定方法/分支标识排序。未知下界为 0 不代表已证明不适用，排除状态独立保存。

另报告逐项权重 ±20% 的八次扰动结果及区间是否严格优于其他方法。这些只是稳定性诊断，不是泛化准确率，也不用于自动宣告可证明或不可证明。全部未知并列时，扰动结果保持无首选，`stable_under_weight_perturbation` 为 false，避免把固定展示顺序解释成稳定分类。

## 可追溯性与验证

`selection/result.json` 包含：源和标准表示哈希、特征、AHP 矩阵与一致性、规则版本及源码/契约指纹、21 条分支的证据和未解决义务、十二方法排名、选择理由、未知项、权重敏感性及选择时间。工作流记录实际选择子进程墙钟时间，包括输入校验开销。

专项测试：

```bash
PYTHONPATH=finite_product_framework python3 -m unittest selection.test_selection -v
```

测试包含合成结构和控制流测试；其中模拟的 `verified` 输入只用于测试特征读取，不是 Lean 证明证据。实际运行只能通过工作流消费核验过的预处理结果。验收结果与真实小样本见 `../generated/selection_20261020/validation.json`。全量 Train 证明率、实际路由损失和对 GPT 的对比尚未测量。
